根据你的 `git log` 输出，当前 `main` 分支的历史非常混乱，包含了大量无意义的提交信息（如 `-`、`FUCK`）以及不必要的合并提交（Merge commit）。

要将这些全部“理顺”并合并成一个干净的提交，最简单且最不容易出错的方法是：**软重置（Soft Reset） + 修正提交（Amend）**。

这种方法会将你所有乱七八糟的提交撤销，但**保留所有的代码改动**，然后让你把它们重新打包成 1 个干净的提交。

请在 PowerShell 中按顺序执行以下步骤：

### 第一步：创建安全备份（至关重要）
以防操作失误，先将当前混乱的状态保存为一个备份分支。
```powershell
git branch backup-messy-history
```
*(如果以后后悔了，可以随时切回这个分支找回所有历史记录)*

### 第二步：软重置到第一个提交
将你当前的 HEAD 指针退回到最早的 "Initial commi" 提交（hash 为 `da6dd0b`）。**注意：这不会删除你的任何代码**，只会把从那个提交之后的所有代码改动，全部放回“暂存区”等待重新提交。
```powershell
git reset --soft da6dd0b
```

### 第三步：合并并生成一个干净的新提交
现在，你之前所有的代码改动都已经准备好了。使用 `--amend` 将它们合并到那个最早的提交中，并赋予一个清晰、专业的提交信息。
```powershell
git commit --amend -m "feat: 项目初始化及核心功能整合 (包含 base, light 等模块)"
```
*(如果你想自己手写提交信息，可以去掉 `-m "..."` 部分，Git 会打开编辑器让你修改，保存并关闭编辑器即可)*

### 第四步：强制推送到远程仓库
因为你修改了本地的提交历史（Commit Hash 已经改变），必须使用强制推送来覆盖远程的 `main` 分支。使用 `--force-with-lease` 是最安全的强制推送方式。
```powershell
git push --force-with-lease origin main
```

---

### 第五步：清理废弃的分支（可选但推荐）
由于你已经把所有分支（`light`, `all`, `base` 等）的代码都整合到了干净的 `main` 分支中，那些指向混乱历史的旧分支已经没有保留价值了。

**删除本地混乱分支：**
```powershell
git branch -D light all base script-analysis-in-the-src-directory-7e28a
```

**删除远程混乱分支：**
```powershell
git push origin --delete light all base script-analysis-in-the-src-directory-7e28a
```

### 总结
执行完上述步骤后，你的 `git log` 将只剩下 1 到 2 个干净的提交，彻底告别“地铁图”。以后在开发新功能时，建议遵循：**在本地分支多提交没关系，但在合并回 `main` 之前，使用 `git rebase -i` 或上述的 `git reset --soft` 方法整理干净后再 Push**。
